অধ্যায় ৯

Unit Testing in Python

তুমি একটা grade বের করার function লিখলে, দুয়েকটা মার্কস দিয়ে চালিয়ে দেখলে ঠিক আছে। এক মাস পর grading নিয়মে ছোট একটা পরিবর্তন করলে। এখন কি নিশ্চিত যে 79.5 মার্কস এখনো ঠিক grade পাচ্ছে? 40-এর সীমায় কী হচ্ছে? প্রতিবার হাতে হাতে সব পরীক্ষা করা অসম্ভব — আর সেখানেই ভুল লুকিয়ে থাকে।

Unit testing এই সমস্যার সমাধান: কোড ঠিকমতো কাজ করছে কিনা সেটা পরীক্ষা করার জন্য আলাদা কোড লেখা, যেটা এক command-এ যতবার খুশি চালানো যায়। এই অধ্যায়ে শিখব unit test কী, কেন জরুরি, এর গঠন, Python-এর built-in unittest library দিয়ে test লেখা ও চালানোর পদ্ধতি, আর test লেখার জন্য কী কী লাগে।

সংজ্ঞা (পরীক্ষার জন্য)

Unit testing হলো software testing-এর এমন একটি পদ্ধতি, যেখানে program-এর সবচেয়ে ছোট পরীক্ষাযোগ্য অংশ — একটি function, method বা class (যাকে unit বলে) — আলাদাভাবে পরীক্ষা করে দেখা হয় যে সেটি প্রত্যাশিত ফলাফল দিচ্ছে কিনা। এই পরীক্ষাগুলো কোড আকারে লেখা হয় এবং স্বয়ংক্রিয়ভাবে চালানো যায়।

বাস্তব উদাহরণ

মোটরসাইকেলের কারখানায় পুরো গাড়ি জোড়া লাগানোর আগে প্রতিটা অংশ — ব্রেক, হেডলাইট, ইঞ্জিন — আলাদা আলাদা পরীক্ষা করা হয়। ব্রেক ঠিক আছে কিনা জানতে পুরো গাড়ি বানিয়ে রাস্তায় নামাতে হয় না। আর একটা অংশ বদলালে শুধু সেই অংশের পরীক্ষা আবার চালানো যায়। Unit testing হলো software-এর এই অংশভিত্তিক মান-পরীক্ষা (quality check)।

সবচেয়ে সরল test লেখা যায় Python-এর assert statement দিয়ে: শর্ত সত্য হলে কিছুই হয় না, মিথ্যা হলে AssertionError।

উদাহরণ 9.1assert দিয়ে প্রথম Test

সমস্যা: একটা add() function আর তার জন্য কয়েকটা test লেখো, যার একটা ইচ্ছা করে ভুল।

লাইন-বাই-লাইন ব্যাখ্যা

assert add(-1, 1) == 0
print("First two tests passed")
দুটো test পাস করেছে, তাই চুপচাপ পরের লাইনে চলে গেছে।
7
assert add(0.1, 0.2) == 0.3, "0.1 + 0.2 should be 0.3"
এই test ব্যর্থ! কারণ computer-এ দশমিক সংখ্যা পুরোপুরি নিখুঁতভাবে রাখা যায় না: 0.1 + 0.2 আসলে 0.30000000000000004। Test ঠিক এই ধরনের অপ্রত্যাশিত আচরণই ধরে ফেলে। এর সমাধান 9.3-এ (assertAlmostEqual)।

assert দিয়ে শুরু করা যায়, কিন্তু প্রথম ব্যর্থতাতেই সব থেমে যায় আর কোন কোন test পাস করল তার হিসাব থাকে না। তাই বাস্তবে ব্যবহার হয় unittest library — যেটা Python-এর সাথেই আসে।

9.2 Unit Testing-এর গুরুত্ব

বাংলাএই টপিকের ভিডিও · মে ২০১৯

Black Box White Box Testing | Unit Testing | Integration Testing | Bangla Tutorial | Edu Clinic

Edu Clinic · YouTube-এ দেখো ↗

  1. শুরুতেই ভুল ধরা পড়ে: কোড লেখার সাথে সাথে ভুল ধরা পড়ে, ব্যবহারকারীর হাতে পৌঁছানোর আগে। যত দেরিতে ভুল ধরা পড়ে, ঠিক করতে খরচ তত বেশি।
  2. নিশ্চিন্তে কোড বদলানো যায়: পুরনো কোড উন্নত (refactor) করার পর test চালালেই বোঝা যায় কিছু ভেঙেছে কিনা। পুরনো ঠিক থাকা কোড নতুন পরিবর্তনে ভেঙে যাওয়াকে বলে regression — unit test এর বিরুদ্ধে পাহারাদার।
  3. Debugging সহজ: কোন test ব্যর্থ হলো দেখেই বোঝা যায় ঠিক কোন function-এ সমস্যা — পুরো program খুঁজতে হয় না।
  4. জীবন্ত document: test পড়লেই বোঝা যায় function কী ইনপুটে কী ফল দেওয়ার কথা — লিখিত বর্ণনার চেয়ে নির্ভরযোগ্য।
  5. ভালো ডিজাইন: test লেখা যায় এমন কোড সাধারণত ছোট, পরিষ্কার, একটা কাজের function — test লেখার অভ্যাস কোডের মান বাড়ায়।
  6. দলগত কাজে আস্থা: অন্যের লেখা কোডে পরিবর্তন করার পর test পাস করলে নিশ্চিত হওয়া যায় যে তার কাজ ভাঙেনি।
  7. সময় ও খরচ সাশ্রয়: শুরুতে test লিখতে সময় লাগে, কিন্তু পরে বারবার হাতে পরীক্ষা আর বড় ভুলের মাশুল থেকে অনেক বেশি সময় বাঁচে।

সম্ভাব্য পরীক্ষার প্রশ্ন

  • Unit testing-এর গুরুত্ব বর্ণনা করো। (4-5 নম্বর)

প্রতিটা পয়েন্টের ছোট শিরোনাম আর এক-দুই লাইনের ব্যাখ্যা। "regression" শব্দটা ব্যাখ্যাসহ ব্যবহার করলে উত্তর মানসম্মত হয়।

Syntax

প্রতিটা test method সাধারণত তিন ধাপে লেখা হয়, যাকে বলে AAA pattern: Arrange (data প্রস্তুত), Act (function চালানো), Assert (ফল যাচাই)।

প্রধান Assertion Method

Methodকী যাচাই করে
assertEqual(a, b)a == b
assertNotEqual(a, b)a != b
assertTrue(x) / assertFalse(x)x সত্য / মিথ্যা

assertAlmostEqual(a, b)a ও b প্রায় সমান (দশমিকের জন্য, 7 ঘর পর্যন্ত)

দশমিক তুলনায় assertAlmostEqual — 9.1-এর 0.1 + 0.2 সমস্যার সমাধান।

    def test_empty_list_raises(self):

    def test_overdraw_not_allowed(self):
        with self.assertRaises(ValueError):
            self.acc.withdraw(5000)
        self.assertEqual(self.acc.balance, 1000)
ব্যর্থ উত্তোলনের পর balance যে অপরিবর্তিত আছে, সেটাও যাচাই — শুধু error হলো কিনা না, ভুল কিছু ঘটেনি তাও দেখা।
21–22
    def test_negative_deposit(self):
        self.assertRaises(ValueError, self.acc.deposit, -50)
assertRaises-এর আরেক রূপ: exception, function, তারপর argument।
24–25
if __name__ == "__main__":
    unittest.main(verbosity=2)
unittest.main() file-এর সব test খুঁজে চালায়, তাই python test_bank.py লিখলেই চলে। verbosity=2 মানে -v-এর মতো বিস্তারিত।

লক্ষ করো, test-এর ক্রম আমাদের লেখার ক্রম নয় — unittest test method-গুলো নামের বর্ণানুক্রমে চালায়। তাই একটা test আরেকটার উপর নির্ভর করবে, এমন test কখনো লিখবে না।

সাধারণ ভুল

ভুল

ফল: NO TESTS RAN

সঠিক

method-এর নাম test_ দিয়ে শুরু হয়নি, তাই unittest এটাকে test হিসেবে চেনেইনি — "Ran 0 tests"। ভুল assertion থাকা সত্ত্বেও কিছুই ধরা পড়েনি, যা আরও বিপজ্জনক।

সম্ভাব্য পরীক্ষার প্রশ্ন

  • unittest library ব্যবহার করে unit test-এর পদ্ধতি বর্ণনা করো। (5 নম্বর)

ধাপগুলো লিখে একটা ছোট module, তার test file আর চালানোর command ও output দেখাও। সম্ভব হলে একটা ব্যর্থ test-এর output-ও দেখাও।

অনুশীলন

একটা string module লেখো যাতে is_palindrome(word) আর count_vowels(text) থাকবে। প্রতিটার জন্য অন্তত তিনটা test লেখো — সাধারণ ক্ষেত্র, ফাঁকা string, আর বড়-ছোট হাতের অক্ষর মেশানো।

9.5 Unit Test লেখা ও চালানোর প্রয়োজনীয়তা

Bangla Python Basic Uniitest Tutorial

Asaduzzaman Sohel · YouTube-এ দেখো ↗

Python-এ unit test লিখতে ও চালাতে যা যা দরকার:

প্রয়োজনীয়তাব্যাখ্যা
Python ও unittestPython install থাকলেই চলে — unittest built-in, আলাদা install লাগে না।
পরীক্ষাযোগ্য কোডকোড module-এ (.py file) ছোট ছোট function বা class-এ ভাগ করা থাকতে হবে, যাতে import করা যায়।
Test file-এর নামtest_ দিয়ে শুরু (test_result.py), যাতে unittest স্বয়ংক্রিয়ভাবে খুঁজে পায়।
importtest file-এ import unittest আর পরীক্ষাধীন module import; দুটো file সাধারণত একই folder-এ।
TestCase classunittest.TestCase থেকে inherit করা class।
Test methodনাম test_ দিয়ে শুরু, প্রথম parameter self।
Assertionপ্রতিটা test-এ অন্তত একটা self.assert…() method।
প্রত্যাশিত ফল জানাকোন ইনপুটে কী ফল আসার কথা আগে থেকে জানতে হবে — সাধারণ, সীমানা ও ভুল ইনপুট।
স্বাধীন ও নির্ধারিত testএকটা test অন্যটার উপর নির্ভর করবে না; প্রতিবার একই ফল দেবে (random বা বর্তমান সময়ের উপর নির্ভর নয়)।
চালানোর উপায়python -m unittest -v test_file অথবা file-এ unittest.main() রেখে python test_file.py; VS Code/PyCharm-এর Testing panel থেকেও চালানো যায়।

Exam Tip

এই প্রশ্নে টেবিলের প্রথম আটটা পয়েন্ট লিখলেই যথেষ্ট। সাথে একটা ছোট test file-এর কাঠামো দিয়ে কোথায় কোন requirement পূরণ হচ্ছে চিহ্নিত করলে পূর্ণ নম্বর।

সম্ভাব্য পরীক্ষার প্রশ্ন

  • Unit test লেখা ও চালানোর জন্য প্রয়োজনীয় বিষয়গুলো উল্লেখ করো। (3-4 নম্বর)

অধ্যায়ের সারসংক্ষেপ

বিষয়মূল কথা
Unit testingprogram-এর ছোট অংশ (function/method/class) আলাদাভাবে, স্বয়ংক্রিয়ভাবে পরীক্ষা।
গুরুত্বশুরুতে ভুল ধরা, regression ঠেকানো, সহজ debugging, document, ভালো ডিজাইন, সময় সাশ্রয়।
গঠনTestCase class, test_ method, assertion, setUp/tearDown fixture, suite, runner; AAA pattern।
পদ্ধতিmodule → test_ file → TestCase → python -m unittest -v → ফল পড়া (. F E, OK/FAILED)।
