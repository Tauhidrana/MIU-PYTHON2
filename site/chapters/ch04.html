Basics of OOP

এতদিন তুমি Python-এ variable, if-else, loop, list আর function দিয়ে program লিখেছ। ছোট program-এর জন্য এই পদ্ধতি চমৎকার। কিন্তু ধরো 40 জন ছাত্রের নাম, রোল, মার্কস রাখতে হবে — আলাদা আলাদা list-এ রাখলে সব গুলিয়ে যায়, আর ফলাফল বের করার function ছাত্রের data চেনেই না, প্রতিবার বাইরে থেকে হাতে তুলে দিতে হয়।

এই অধ্যায়ে আমরা সেই সমস্যার সমাধান শিখব — Object Oriented Programming। প্রথমে দেখব OOP আসলে কী, কেন এটা দরকার আর এর বৈশিষ্ট্য কী কী। তারপর নিজের হাতে Class আর Object বানাব, Constructor আর self কীভাবে কাজ করে সেটা লাইন ধরে ধরে বুঝব, আর শেষে Class দিয়ে কয়েকটা পূর্ণ program লিখব।

তাহলে OOP কী?

সংজ্ঞা (পরীক্ষার জন্য)

Object Oriented Programming (OOP) হলো একটি programming পদ্ধতি, যেখানে program-কে কতগুলো object-এর সমষ্টি হিসেবে সাজানো হয়। প্রতিটি object-এর ভেতরে তার নিজের data (attribute) এবং সেই data নিয়ে কাজ করার function (method) একসাথে থাকে। Object তৈরি হয় class নামের একটি নকশা থেকে।

সহজ কথায়: Procedural programming-এ আমরা ভাবি "কী কী কাজ করতে হবে"। OOP-এ আমরা ভাবি "program-এ কী কী জিনিস (object) আছে, প্রতিটার কী তথ্য আছে আর সে কী কী করতে পারে"।

বাস্তব উদাহরণ

তোমার মোবাইল ফোন একটা object। এর কিছু তথ্য আছে: battery কত শতাংশ, কোন কোন contact সেভ করা, ফোনের model কী — এগুলো তার attribute। আবার ফোন কিছু কাজ করতে পারে: call করা, message পাঠানো, ছবি তোলা — এগুলো তার method। তুমি battery-র ভেতরে হাত দিয়ে চার্জ বাড়াও না, charger লাগাও; ফোন নিজেই নিজের battery-র হিসাব রাখে। তথ্য আর কাজ একসাথে একটা জিনিসের ভেতরে — এটাই OOP-এর মূল ভাবনা।

4.2 OOP-এর গুরুত্ব

ছোট program-এ OOP-এর সুবিধা চোখে পড়ে না, কখনো কখনো বরং একটু বেশি লেখা লাগে। কিন্তু program যত বড় হয় — হাজার হাজার লাইন, অনেকজন programmer, বছরের পর বছর রক্ষণাবেক্ষণ — OOP তত দরকারি হয়ে ওঠে। প্রধান কারণগুলো দেখি:

  1. বাস্তব জগতের মতো করে program সাজানো যায়। স্কুল ব্যবস্থাপনা software-এ Student, Teacher, Course — বাস্তবের এই জিনিসগুলোই program-এ object হয়ে আসে। তাই program-এর নকশা বুঝতে সহজ হয়, এমনকি যে programming জানে না সেও বুঝতে পারে কোন অংশ কী।
  2. কোড বারবার ব্যবহার করা যায় (Reusability)। একটা Student class একবার লিখে তা থেকে হাজারটা object বানানো যায়। আবার Inheritance দিয়ে পুরনো class-এর সব সুবিধা নিয়ে নতুন class বানানো যায়, শুরু থেকে লিখতে হয় না।
  3. রক্ষণাবেক্ষণ সহজ (Maintainability)। ছাত্রের তথ্য দেখানোর ধরন বদলাতে চাইলে শুধু Student class-এর show() method বদলাও — সব ছাত্রের ক্ষেত্রে একসাথে বদলে যাবে। কোথাও ভুল হলে খুঁজতে হয় একটাই জায়গায়।
  4. Data সুরক্ষিত রাখা যায় (Security)। Encapsulation-এর মাধ্যমে object-এর গুরুত্বপূর্ণ data বাইরে থেকে সরাসরি বদলানো বন্ধ করা যায়। যেমন ব্যাংক অ্যাকাউন্টের balance কেউ সরাসরি লিখে বদলাতে পারবে না, deposit() বা withdraw() দিয়েই বদলাতে হবে।
  5. দলগতভাবে কাজ করা সহজ (Team Work)। বড় project-এ একজন Student class, আরেকজন Course class, আরেকজন Result class লিখতে পারে। প্রত্যেকে নিজের অংশে কাজ করে, অন্যের কোড ভাঙার ভয় কম।
  6. নতুন feature যোগ করা সহজ (Scalability)। নতুন ধরনের ছাত্র (যেমন Diploma বা Short Course-এর ছাত্র) যোগ করতে আগের কোড না ভেঙে নতুন class যোগ করলেই হয়।

  • OOP কীভাবে code reusability নিশ্চিত করে?

প্রতিটি পয়েন্টের একটা ছোট শিরোনাম আর তার নিচে এক-দুই লাইনের ব্যাখ্যা লেখো। শুধু শব্দের তালিকা লিখলে পূর্ণ নম্বর পাওয়া যায় না।

একটা programming পদ্ধতিকে Object Oriented বলা হয় কিছু নির্দিষ্ট বৈশিষ্ট্যের জন্য। নিচের টেবিলে প্রধান বৈশিষ্ট্যগুলো দেওয়া হলো। এর মধ্যে Encapsulation, Inheritance, Polymorphism আর Abstraction-কে বলা হয় OOP-এর চার স্তম্ভ (Four Pillars) — এদের নিয়ে পুরো অধ্যায় ৫। এখানে শুধু ধারণাটা পরিষ্কার করে রাখি।

বৈশিষ্ট্যসহজ অর্থবাস্তব উদাহরণ

EncapsulationData আর method একসাথে বেঁধে রাখা এবং data বাইরে থেকে সুরক্ষিত রাখাক্যাপসুলের ভেতরে ওষুধ; ATM-এর ভেতরের টাকা
Abstractionভেতরের জটিলতা লুকিয়ে শুধু দরকারি অংশ দেখানোগাড়ি চালাতে ইঞ্জিনের ভেতরটা জানতে হয় না
Inheritanceএকটা class অন্য class-এর বৈশিষ্ট্য উত্তরাধিকার সূত্রে পায়সন্তান বাবা-মায়ের কিছু বৈশিষ্ট্য পায়
Polymorphismএকই নামের কাজ ভিন্ন object-এ ভিন্নভাবে হয়"শব্দ করো" বললে কুকুর ঘেউ ঘেউ, বিড়াল মিউ মিউ

এতক্ষণ Class আর Object শব্দ দুটো অনেকবার এসেছে। এবার এদের ঠিকঠাক চিনি।

সংজ্ঞা (পরীক্ষার জন্য)

Class হলো object তৈরির একটি নকশা (blueprint) বা ছাঁচ (template)। Class-এ বলা থাকে এই ধরনের প্রতিটা object-এর কী কী data (attribute) থাকবে এবং সে কী কী কাজ (method) করতে পারবে।

Object হলো class থেকে তৈরি একটি বাস্তব উদাহরণ (instance)। প্রতিটা object-এর নিজস্ব data থাকে, কিন্তু সবাই একই class-এর নিয়ম মেনে চলে।

বাস্তব উদাহরণ

পিঠা বানানোর ছাঁচের কথা ভাবো। ছাঁচ একটাই, কিন্তু সেই ছাঁচ দিয়ে তুমি পঞ্চাশটা পিঠা বানাতে পারো। সব পিঠার আকার এক, কারণ ছাঁচ এক। কিন্তু কোনোটার ভেতরে নারকেলের পুর, কোনোটায় খেজুরের গুড়। এখানে ছাঁচ হলো class, প্রতিটা পিঠা একটা object, আর ভেতরের পুর হলো সেই object-এর নিজস্ব data। ছাঁচ নিজে খাওয়া যায় না — class নিজে কোনো data রাখে না, data থাকে object-এ।

Class তৈরি এবং Object বানানো

Method: Object-এর কাজ

Class-এর ভেতরে লেখা function-কে বলে method। Method সেই class-এর প্রতিটা object ব্যবহার করতে পারে। Method-এর প্রথম parameter সবসময় self — এর মানে 4.5-এ বিস্তারিত বুঝবে, আপাতত এটুকু মনে রাখো যে এটা লিখতেই হবে।

Constructor: __init__()

4.4-এ দেখেছ, বাইরে থেকে attribute দিলে ভুলে যাওয়ার ঝুঁকি থাকে। Constructor এই সমস্যার সমাধান। Python-এ constructor হলো __init__ নামের একটা বিশেষ method (init-এর দুই পাশে দুটো করে underscore)। এর বিশেষত্ব হলো: object তৈরি হওয়ার সাথে সাথে Python নিজে থেকেই এটা ডাকে। তোমাকে কখনো s1.__init__() লিখতে হয় না।

self: "আমি নিজে"

নতুনদের কাছে OOP-এর সবচেয়ে রহস্যময় শব্দ হলো self। আসলে ব্যাপারটা সহজ: self মানে যে object-এর জন্য method-টা চলছে, সেই object নিজে। s1.show() ডাকলে show()-এর ভেতরে self মানে s1; s2.show() ডাকলে self মানে s2।

ক্লাসে শিক্ষক সবাইকে বললেন: "সবাই নিজের খাতা খোলো।" কথা একটাই, কিন্তু Rahim খোলে Rahim-এর খাতা, Sumaiya খোলে Sumaiya-র খাতা। "নিজের" শব্দটা প্রত্যেকের ক্ষেত্রে আলাদা মানুষকে বোঝায়। Method-এর ভেতরে self ঠিক এই "নিজের"। Method-এর কোড একটাই, কিন্তু self.name লিখলে যে object ডেকেছে তার নিজের name পাওয়া যায়।

Class Design করার ধাপ

  1. সমস্যায় কোন "জিনিস" (noun) আছে খুঁজে বের করো — এরা class হবে। (Student, Account, Rectangle)
  2. প্রতিটা জিনিসের কী কী তথ্য আছে লেখো — এরা attribute হবে। (name, balance, length)
  3. প্রতিটা জিনিস কী কী কাজ করে লেখো (verb) — এরা method হবে। (deposit, area, result)
  4. কোন তথ্য object তৈরির সময়েই লাগবে ঠিক করো — এরা constructor-এর parameter হবে।
  5. তারপর কোড লেখো, ছোট একটা object বানিয়ে প্রতিটা method আলাদা করে পরীক্ষা করো।

Program লেখার প্রশ্নে কোডের পর অবশ্যই একটা নমুনা output লিখবে। Class-এর নাম PascalCase-এ, method-এ self — এই ছোট জিনিসগুলোতেই সবচেয়ে বেশি নম্বর কাটা যায়।

MethodClass-এর ভেতরের function; প্রথম parameter self; object.method() দিয়ে ডাকা হয়।
